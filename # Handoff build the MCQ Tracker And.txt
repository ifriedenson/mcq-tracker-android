## Product goal (v1)

A fast, offline Android app that opens an Obsidian vault folder, finds MCQ Tracker question notes, lets the user practise them, schedules reviews with the plugin's default ladder, and writes compatible review state back to the notes.

In scope:

- A bundled sample vault so the app is usable on first launch.

## Note-format contract

A question note is Markdown with YAML frontmatter. `question_id` is required. Example:

```markdown
---
question_id: SAMPLE-001
course: Sample Course
skill: Reading
difficulty: easy
choices: 4
answer: C
target_seconds: 60
---

## Question

In the sentence "The experiment was inconclusive, so the team repeated it," what does "inconclusive" most nearly mean?

## Answer Choices

- A. Dangerous
- B. Expensive
- C. Not decisive
- D. Carefully planned

## Answer

> [!answer]- Reveal answer
> **Correct Answer: C**
>
> Inconclusive means the results did not settle the question.
```

Read these properties:
`question_id, course, test, section, domain, skill, difficulty, unit, question_type,
answer, choices, target_seconds, stimulus_id, scheduler, study_status, known_until,
attempts, correct_count, streak, next_review, result, last_confidence,
last_error_type, time_spent_total, last_time_spent, flagged, history`.

Section aliases (case-insensitive, strip `* _ \``):
- Stimulus: `stimulus`, `passage`, `source`, `excerpt`, `reading`, `text`, `figure`
- Question: `question`, `stem`, `prompt`
- Hint: `hint`, `clue`
- Choices: `answer choices`, `choices`, `options`, `answers choices`
- Answer: `answer`, `answer key`, `correct answer`, `answer and rationale`, `solution`
- Notes: `my notes`, `notes`

Choices: lines like `- A. text`, `- A) text`, `- A: text`, optionally bolded. Support wrapped continuation lines. Letters A–H.

Answer-key precedence:
1. Frontmatter `answer`, `correct_answer`, `correct`, `answer_key`, `key`.
2. Choice sets such as `A, C`, `A/C`, `A and C`, `AC` (normalize sorted, comma-separated).
3. Single letter.
4. `## Answer` text patterns: `Correct Answer: B`, `**Answer:** B`, `The correct answer is C`, `Correct Answers: A, C`, `Correct Answer: False`.
5. Otherwise self-graded.

Mode inference, matching the plugin:
- `question_type` containing `spr`, `student-produced`, `grid-in`, `free-response`, `short-answer`, `numeric`, `fill` → self-graded.
- `select_all`, `sata`, `multi-select`, `multi-answer`, `checkbox` → select-all.
- `true_false`, `boolean`, `tf` → true/false.
- `mcq`, `multiple`, `choice`, `select` → MCQ or select-all if the key is a set.
- A set key → select-all; choices that are exactly True/False → true/false; a full-word True/False key with no choices → true/false; a single letter → MCQ.
- No key → self-graded.
- If MCQ/select-all has fewer than two choices, downgrade to self-graded rather than showing an unanswerable screen.

Normalize:
- MCQ key to uppercase.
- Select-all key to sorted `A, C`.
- True/false key to canonical `True` or `False`, mapping letters through the note's own choices.
- Self-graded keeps the raw key for display.

Also:
- If `## Stimulus` is absent but `stimulus_id` is present, borrow the stimulus from another loaded note with the same `stimulus_id`.
- Read `study_status`: `excluded` and `suspended` are never queued; `known` is queued only when `known_until` is today or earlier. Do not rewrite these statuses.
- Strip Markdown to readable plain text for display. Do not attempt LaTeX/MathJax rendering in v1.

## Grading contract

- MCQ: chosen letter equals key, case-insensitive.
- Select-all: exact set equality. Missing or extra choices are wrong.
- True/false: compare canonical values, mapping letter keys through choices.
- Self-graded: user taps "I got it right" or "I got it wrong"; the history answer field is empty.
- Confidence labels: 1 = Guessing, 2 = Unsure, 3 = Confident. Default 2.

## Scheduling contract (exact)

Intervals: `[1, 3, 7, 21, 60]` days.

On submit:

```text
conf = clamp(confidence, 1, 3)
if correct:
    streak = (conf == 1) ? previousStreak : previousStreak + 1
    intervalDays = (conf == 1)
        ? 2
        : intervals[min(max(streak, 1) - 1, 4)]
else:
    streak = 0
    intervalDays = 1

next_review = localToday + intervalDays
attempts += 1
correct_count += (correct ? 1 : 0)
time_spent_total += seconds
last_time_spent = seconds
last_result = correct ? "correct" : "incorrect"
last_confidence = conf
last_error_type = ""
```

This means: first correct → 1 day, second → 3, third → 7, fourth → 21, fifth and later → 60. A correct guess (confidence 1) returns in 2 days and does not advance the streak. A miss returns tomorrow and resets the streak.

## Write-back contract

Only write when all are true:
- The user enabled write-back.
- The note came from an SAF file (not the bundled sample).
- `scheduler` is not `fsrs` and not `sm2` (and `srs` / `sm2` state should be treated as scheduler-managed even if the scheduler property is missing).

Write these top-level properties, preserving the note body and line endings:

- `result`: `correct` or `incorrect`
- `date attempted`: `yyyy-MM-dd'T'HH:mm` (local, minutes)
- `first_attempted`: set only if missing or empty; same format
- `attempts`: integer
- `correct_count`: integer
- `streak`: integer
- `time_spent_total`: integer seconds
- `last_time_spent`: integer seconds
- `last_answer`: chosen letter(s), or empty for self-graded
- `last_confidence`: 1–3
- `last_error_type`: empty after an attempt; tag value after an error tag
- `next_review`: `yyyy-MM-dd`
- `last_attempt_id`: UUID
- `history`: list of rows

Do not modify `srs`, `sm2`, `scheduler`, `flagged`, `study_status`, or the note body. Do not write these fields into FSRS/SM-2 notes.

History row format:

```text
yyyy-MM-dd'T'HH:mm:ss|correct|seconds|chosen|confidence|error_type|attempt_id
```

- `result` is `correct` or `incorrect` (skips are not implemented in v1).
- Replace `|`, newlines and carriage returns inside `chosen` with `/` or a space.
- Append only if the same attempt ID is not already present.
- Preserve any optional eighth `variant` field on existing rows; never drop it.
- Parse and preserve existing rows, including quoted YAML list entries.
- On a write, replace the whole `history` list with the local list, but only after verifying the note has not changed externally.

Error tags must use the plugin's exact values:
`careless`, `content gap`, `misread`, `ran out of time`, `guessed`.

## Write safety

Before writing:
1. Re-read the note from SAF.
2. Compare a content signature (or last-modified time) with the version loaded into memory.
3. If it changed, abort the write and keep progress locally; show a message that the note was changed elsewhere.
4. Write once, with `openOutputStream(uri, "wt")`. On failure, keep local progress and tell the user the note was not updated.

Do not silently overwrite concurrent Obsidian edits. Do not add backups inside the vault unless the user asks. Default write-back to **off** on first launch; let the user enable it in Settings after explaining what is written. Show clear state after each answer: "Saved to note", "Saved in app only", or "Note changed elsewhere — saved in app only".

## Local progress

Store a local mirror of every question's progress in SharedPreferences as JSON, keyed by `sourceKey::question_id`:
- `sourceKey` = `"sample"` or the SAF tree URI.
- Store attempts, correct count, streak, next review, last result, last confidence, last error type, seconds, history, flagged.

On load, merge the note and local copy:
- Prefer the local copy if it has more attempts.
- If attempts are equal, prefer the one with more history rows.
- If attempts and history are equal, prefer a non-empty local error tag over an empty note tag.
- Otherwise use the note.

FSRS/SM-2 notes are read-only: keep their progress locally so due reviews still work in the app, but never write those notes.

- Use `Dispatchers.IO` for file work. Never block the main thread.
- `Question.key = "$sourceKey::$questionId"`.
- Keep raw note text in the Question until write-back.
- After a successful write, update the in-memory raw text and progress.
- `SourceKey` for sample = `sample`.
